האלגוריתם והמתמטיקה

איך עובד מודל הניקוד ורף המינימום?

נוסחת חישוב ציון ההתאמה (Match Score):
Score = 100 * (1.0 - Σ [ w_i * (|P_seeker,i - P_host,i| / MaxDist_i) ])

כל קריטריון רך מקבל משקל יחסי. מרחק אפס מניב התאמה מושלמת (100%).

רף מינימום דינמי לבחירת המשתמש:

משתמש יכול לקבוע לעצמו min_match_threshold = 75%. המערכת תסנן מראש מועמדים שקיבלו ציון נמוך מ-75%.

אם המשתמש בחר לא להגדיר רף (None), המערכת תציג את כלל המועמדים התקינים בסדר יורד.

מחלקת הבסיס האבסטרקטית: User(ABC)

Abstract Base Class

תכונות (Attributes) ובנאי ראשי:

  • • user_id: str – מזהה ייחודי למשתמש
  • • name: str – שם מלא של המשתמש
  • • _age: int – שדה מוגן (Encapsulated) עם Property
  • • phone: str – טלפון לחשיפה בעת Match
  • • preferences: Preferences – אובייקט הרכבה
הגנה מפני יצירה ישירה: ירושה מ-ABC מונעת יצירת אובייקט ישיר (TypeError) ומבטיחה יישום החוזה על ידי המחלקות היורשות.

מתודות אבסטרקטיות, ולידציה ו-Dunder:

@abstractmethod get_role_summary() -> str

חוזה מחייב: החזרת מחרוזת תיאור תפקיד ספציפי למחלקות היורשות.

@abstractmethod evaluate_dealbreakers(other) -> bool

חוזה מחייב: בדיקה פולימורפית לפסילה מול משתמש אחר.

Encapsulation (@age.setter):

בדיקה ש-age >= 18. חריגה תזרוק ValueError("גיל המשתמש חייב להיות לפחות 18").

__str__ ו-__repr__:

הצגה ידידותית מול הצגת פיתוח מלאה לדיבאגינג.

מחלקת הנכס: Apartment וניהול האוסף

Composition & Collection Ops

ניהול אוסף המתקנים (Amenities Collection):

המחלקה מחזיקה אוסף פנימי מסוג set (ממ"ד, מרפסת, מעלית, מזגן). כדי לענות על דרישת סעיף 2 במחוון, ממומשות 3 פעולות מפורשות על האוסף:

1. add_amenity(amenity: str) -> None

מוסיפה מתקן חדש לקבוצה (שימוש ב-add של set).

2. remove_amenity(amenity: str) -> None

מסירה מתקן בבטחה באמצעות discard כדי למנוע קריסה.

3. has_amenity(amenity: str) -> bool

בדיקת שייכות מתקן באמצעות אופרטור in בסיבוכיות O(1).

ולידציה, Property מחושב ומתודה סטטית:

Validation על שכר דירה (@rent.setter):

בדיקה ש-rent > 0. נתון שלילי או אפס זורק ValueError("שכר הדירה חייב להיות מספר חיובי").

Computed Property (@property price_per_room):

מחשב דינמית שכר דירה ממוצע לחדר: rent / rooms_total.

Static Method (@staticmethod is_valid_city):

פעולת עזר לבדיקה ששם העיר אינו ריק ומופיע ברשימת הערים הנתמכות.

בנאי אלטרנטיבי:

from_dict(cls, data) הממיר רשימת amenities ל-set.

מחלקות הסיוע: Preferences ו-Match

Encapsulation & Matching

🧬 Preferences (ניהול 22 הקריטריונים)

  • • _cleanliness: int – סולם 1 עד 5 מוגן ב-Property
  • • allows_pets / is_smoker: bool – קריטריוני סף
  • • sleep_schedule / work_mode: str – שגרה
  • • kashrut_level / shabbat_observant: str – כשרות ומסורת
Validation קפדני:

אם cleanliness אינו מספר שלם בין 1 ל-5, נזרק ValueError("Cleanliness must be between 1 and 5").

מתודות עסקיות ו-Dunder:

• has_conflict(other) – זיהוי פסילה בינארית.

• compatibility_score(other) – חישוב ציון משוקלל.

• __eq__ – השוואת שוויון העדפות מלאה.

🤝 Match (ישות התאמה עסקית)

מייצגת חיבור הדדי בין שני משתמשים שהתבצע עליו Like הדדי.

  • • match_id: str – מזהה ייחודי לחיבור
  • • seeker_id: str – מזהה מחפש הדירה
  • • host_id: str – מזהה בעל החדר
  • • score: float – ציון ההתאמה הסופי (0 עד 100%)
  • • status: str – מצב ההתאמה ("pending" / "confirmed")
הכנה קריטית לתור עדיפויות (HeapQ):

• מימוש מתודת __lt__(self, other) לפי ציון ההתאמה (self.score < other.score).

מאפשר לשלוף ישירות מ-heapq את ה-Match הטוב ביותר ללא שום קוד מיון נוסף!
